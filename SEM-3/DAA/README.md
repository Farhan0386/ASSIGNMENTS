# Mini-Courier Planner

An educational, reproducible Python prototype that prioritizes parcels, chooses a capacity-feasible delivery batch, computes shortest road paths, and plans an approximate multi-stop route.

## Requirements

- Python 3.10 or newer
- Matplotlib (only needed to regenerate the runtime chart)
- Jupyter (optional, to open the notebook)

## Run

From this directory:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.main
```

On macOS/Linux, activate with `source .venv/bin/activate`. The planner itself uses only the Python standard library. If matplotlib is unavailable, the application still runs; only chart generation is skipped.

Run automated correctness checks with `python -m unittest discover -s tests -v`. Rebuild performance observations and chart with `python -m src.benchmark --output images/runtime_benchmarks.png --csv results/benchmark_results.csv`. Open `mini_courier_planner.ipynb` in Jupyter for an interactive walkthrough.

## Problem and algorithm choices

Parcel ranking uses stable merge sort with an explicit priority/deadline/ID key, giving predictable O(n log n) time. Batch selection uses 0/1 knapsack dynamic programming to maximize the sum of parcel priority scores under the vehicle's weight capacity; a stable tie rule favors lighter solutions. The road network is an undirected weighted adjacency list. Dijkstra's algorithm computes all needed shortest paths from the depot (O((V+E) log V) with the binary heap). The planner then applies nearest-neighbor TSP approximation to the selected destinations using those shortest-path distances (O(k²)); this is a heuristic, not an optimality guarantee. The displayed route distance sums real shortest road paths, and each leg can be expanded into road vertices.

This is a planning prototype, not a live dispatch system: road weights are nonnegative travel-distance units, delivery windows are represented by priority ranking rather than time-window feasibility, and parcel value is an educational priority score rather than money.

## Inputs and outputs

`datasets/parcels.json` defines parcel IDs, destination node, weight, deadline, and priority. `datasets/road_network.json` defines nodes, undirected weighted edges, and the depot. Run the CLI to see parcel ranking, selected batch and used capacity, shortest paths, expanded delivery route, total distance, and measured component times. `results/sample_run.txt` records a reference run.

## Reproducibility and limitations

Benchmark cases are deterministically generated at several graph and parcel sizes. Timings are machine-dependent and should be interpreted as observations, not universal performance claims. The runtime chart and CSV are generated by the benchmark command. The road network must be connected for the selected destinations; unreachable destinations fail with a clear exception. Knapsack complexity is pseudo-polynomial O(nW) time and O(nW) space, where W is the integer capacity in weight units.
